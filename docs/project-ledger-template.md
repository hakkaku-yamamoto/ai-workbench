# プロジェクト台帳（ひな型）

複数アプリの開発・運用状況を 1 か所で把握するための台帳のひな型。

## このファイルの扱い（重要）

**このリポジトリは Public である。実際の台帳をここに置かない。**

- このファイルは**ひな型（項目の定義と記入例）のみ**である。
  記入例はすべて架空の値（`example-*`）であり、実在のアプリ名・パス・
  リポジトリ名・環境識別子は含まない。
- **記入済みの台帳は Private 領域で管理する。**
  （[ARCHITECTURE.md](ARCHITECTURE.md) 7.2 の分離設計に従う）
- 本番環境の識別情報、接続情報、バックアップの保存先などは
  [../.claude/rules/safety.md](../.claude/rules/safety.md) 第 4 節により
  Public リポジトリに置けない。

## 管理構成（計画）

| パス | 用途 |
| :- | :- |
| `C:\AI-DEV` | 開発用リポジトリの作業コピーを集約する |
| `C:\AI-DOCS` | 設計資料・台帳・運用文書を集約する |

**現状（READ ONLY で確認した事実）**

- `C:\AI-DEV` と `C:\AI-DOCS` はどちらも**存在する**。
- ただし**各アプリの作業コピーはまだこの構成に集約されていない。**
  ユーザー配下の複数の場所に Git リポジトリが分散している。
- 具体的な所在とアプリ名は、Public であるこの文書には記載しない。

**移行についての注意**

- 既存のフォルダ・リポジトリ・バックアップの**移動・削除・上書きは行わない。**
  集約するかどうか、どう移すかは人間の判断事項である。
- 作業コピーの場所を変える場合、Claude Code のセッションは
  **プロジェクトルートを起点に起動する必要がある**
  （起点が違うとプロジェクト設定と Hooks が読み込まれない。
  [ARCHITECTURE.md](ARCHITECTURE.md) 11-5）。

## 台帳の項目

| 項目 | 内容 | 記入の注意 |
| :- | :- | :- |
| アプリ名 | 識別名 | Private 台帳にのみ実名を書く |
| ローカル保存場所 | 作業コピーの絶対パス | 推測で書かない。実際に確認したパスのみ |
| GitHub リポジトリ | `owner/repo` と可視性（Public / Private） | 可視性を必ず記録する。Public なら秘密情報の扱いが変わる |
| 既定ブランチ | `main` 等 | 保護設定の対象を特定するため |
| ブランチ保護 | Ruleset の有効/無効、PR 必須・削除禁止・force push 禁止、必要承認数 | 未設定なら開発を始めない判断材料になる |
| 開発環境 | 言語・バージョン、フレームワーク、起動方法、テスト/Lint/型チェックのコマンド | コマンドは**中身を検証済か**も記録する |
| 本番環境の識別情報 | 環境の区別に使う情報（**実際の接続情報は書かない**） | 接続情報・認証情報は秘密情報管理へ。台帳には「どこを見れば分かるか」のみ |
| 非本番環境 | dev / staging / preview の有無と、共有かどうか | 共有環境は承認で環境名を明示する必要がある |
| 開発状況 | 現在の工程、進行中の作業、ブロッカー | |
| 関連ドキュメント | 設計資料・運用手順の所在 | |
| バックアップの管理先 | 何を・どこに・どの頻度で・誰が | **削除・上書きは人間が行う**（safety.md 1-a） |
| 最終確認日 | この行を確認した日付 | 古い情報を信じないため |

## 記入例（すべて架空の値）

| 項目 | 記入例 |
| :- | :- |
| アプリ名 | `example-app` |
| ローカル保存場所 | `C:\AI-DEV\example-app` |
| GitHub リポジトリ | `example-owner/example-app`（Private） |
| 既定ブランチ | `main` |
| ブランチ保護 | Ruleset `protect-main` / active / PR 必須・削除禁止・force push 禁止 / 必要承認数 1 |
| 開発環境 | Node.js 22 / Next.js / `npm run dev` / テスト `npm run test`（中身を検証済） |
| 本番環境の識別情報 | 環境変数 `APP_ENV=production` で判別。接続情報は秘密情報管理サービスを参照 |
| 非本番環境 | `staging`（共有。使用には環境名を明示した承認が必要） |
| 開発状況 | 実装中 / ブロッカーなし |
| 関連ドキュメント | `C:\AI-DOCS\example-app\` |
| バックアップの管理先 | 日次。保存先は Private 台帳に記載 |
| 最終確認日 | `YYYY-MM-DD` |

## 運用

1. **アプリを追加したら 1 行追加する。**
2. **作業を始める前にその行を確認する。**
   特にブランチ保護・可視性・テストコマンドの検証状況。
3. **最終確認日が古い行は信用しない。** 再確認してから使う。
4. 台帳の項目が足りなくなったら、このひな型も更新する。

## タスクスコープ承認との関係

台帳は、タスクスコープ承認の 7 項目
（[../.claude/rules/approval.md](../.claude/rules/approval.md) 第 7 節）を
書くときの材料になる。

| 承認の項目 | 台帳から取れるもの |
| :- | :- |
| 1. 対象リポジトリ | GitHub リポジトリ |
| 5. 作業ブランチ | 既定ブランチ（これ以外を作業ブランチにする） |
| 7. 完了条件とテスト条件 | 開発環境のテスト/Lint/型チェックのコマンド |

残りの項目（目的・変更を許可する範囲・変更禁止の対象・許可する Git 操作）は
タスクごとに人間が決める。
