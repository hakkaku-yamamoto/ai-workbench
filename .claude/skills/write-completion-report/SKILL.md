完了報告を作成します。適用するルールは `.claude/rules/reporting.md` です。

## 原則

- **実施したことだけを実施したと書く。**
- 未実施・未検証・失敗を省略しない。
- 成果を実際より良く見せない。
- 断定は、ツールの出力で裏付けられる内容にのみ使う。

## 事実・推測・実行結果を書き分ける

| 区分 | 書き方 |
| :- | :- |
| 確認した事実 | 「〜であることを確認した」＋ 根拠（出力・ファイル内容） |
| 実行結果 | 「〜を実行し、〜という結果だった」＋ 実行したコマンド |
| 推測・設計判断 | 「〜と考えられる」「〜を前提とした」＋ 根拠と前提 |
| 未検証・未実施 | 「〜は実施していない」「〜は確認できていない」＋ 理由 |

## 必ず含める項目

1. 事前確認（GATE）の判定結果
2. 対象（リポジトリ、HEAD SHA、ブランチ、環境）
3. 実施した操作の一覧
4. 作成・変更・削除したファイルの一覧と、それぞれの役割
5. 実装した内容
6. 技術的ガードの範囲と**限界**
7. 検証結果（実施した検証とその結果。**未実施も明記**）
8. 未解決事項
9. 次に必要な承認
10. 総合判定

## 一括承認で進めた場合の追加項目

人間が途中を見ていないため、**何を自動で実行したかを残すことが必須**になる。

1. 承認された範囲（7 項目の再掲）
2. 自動実行した操作の一覧
   - 作成・変更したファイル（パスと変更の要点）
   - 実行したテスト・Lint・型チェックとその結果
   - 修正と再テストの回数、最終的に通ったか
   - 実行した Git 操作（commit SHA、push 先ブランチ、PR 番号）
3. 範囲内に収まっていることの確認結果
4. STOP 条件に該当しなかったこと、または該当して中断した内容
5. 判断した事項（人間に確認せず決めたこと）と根拠
6. 完了条件を満たしたかの判定
7. **実行していない操作**（承認に含まれていなかったため実行しなかったもの）

## 総合判定

| 判定 | 条件 |
| :- | :- |
| `PASS` | 依頼範囲をすべて完了し、実行可能な検証がすべて成功し、未解決の懸念がない |
| `PASS_WITH_WARNINGS` | 範囲は完了したが、注意事項・未検証項目・設計上の留保がある |
| `BLOCKED` | 事前確認で停止した、STOP 条件に該当した、または範囲を完了できなかった |

判定の指針：

- **未検証の項目が残っている場合、`PASS` ではなく `PASS_WITH_WARNINGS` とする。**
- 「おそらく問題ない」は `PASS` の根拠にならない。
- 一部でも完了できなかった範囲があれば `BLOCKED` を検討する。
- **判定を良く見せるために未解決事項を省略しない。**

## 書式

- 依頼者が形式を指定した場合はそれに従う
- 単一のコードブロックで提出するよう指定された場合は、内部に別のコードブロックを
  作らない。途中で閉じず、最後に 1 回だけ閉じる
- **秘密情報（鍵・トークン・パスワード・接続文字列）を報告に含めない。**
  値そのものを出力しない
- 冗長な自己評価・謝罪・反省を書かない。事実と次の行動を書く
