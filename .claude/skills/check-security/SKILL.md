---
name: check-security
description: 秘密情報の混入、権限設定、依存関係、Publicリポジトリ適合性を検査する。commitやpushの前、または変更をレビューするときに使う。検出した値そのものは出力しない。
---

安全性を検査します。**検出した秘密情報の値そのものは出力しません。**
パターン名・ファイル・行番号のみを報告します。

## 検査は大文字小文字を区別しない

過去に区別する検査を使って検出漏れが発生している。
必ず `grep -i`（または `-ni`）を使う。

## 1. 秘密情報（変更差分の追加行を対象）

```
git diff --cached   # ステージ済
git diff            # 未ステージ
```

検査するパターン：

| 種別 | 例 |
| :- | :- |
| 認証情報 | `gh[pousr]_` / `sk-` / `AKIA` / `AIza` / `xox[baprs]-` / JWT / `BEGIN ... PRIVATE KEY` |
| 代入形式 | `password` / `passwd` / `secret` / `token` / `api_key` / `access_key` / `private_key` / `client_secret` に値が付いているもの |
| 接続文字列 | `postgres` / `mysql` / `mongodb` / `redis` / `amqp` の URL に認証情報を含むもの |
| 個人情報 | メールアドレス、電話番号、個人のファイルパス |
| ネットワーク | 内部ホスト名、内部 IP、IPv4 リテラル |
| 鍵ファイル | `.pem` / `.key` / `.p12` / `.pfx` / `.jks` / `.keystore` の追加 |

## 2. 社内固有情報（Public リポジトリの場合）

- 社内アプリ名・プロダクト名（公開済みと確認できないもの）
- 部署名、担当者名、取引先名、顧客名
- 社内固有の業務ルール、本番環境固有の設定

**検査対象の名称リストは人間から受け取る。** リストにない名称は検出できないため、
その限界を報告に含める。

## 3. `.gitignore` の実効性

```
git check-ignore -q <path> && echo IGNORED || echo "NOT ignored"
```

`.env` 系・鍵・認証情報・`settings.local.json` が除外されているかを確認する。
`.env.example` のようなテンプレートが誤って除外されていないかも確認する。

## 4. 権限・設定

- `.claude/settings.json` の `deny` / `ask` が弱められていないか
- `allow` に危険な操作（パッケージマネージャの run、依存インストール、
  `git add` の無条件許可など）が追加されていないか
- `bypassPermissions` が使われていないか
- Hooks が無効化・書き換えられていないか

## 5. 依存関係

- 新しい依存の追加（名前・バージョン・用途）
- ロックファイルの変更
- インストール時に任意のコードが走る依存（`postinstall` 等）

## 6. 入力の扱い

- 外部入力をそのまま実行・評価していないか
- ファイルパスの組み立てに未検証の入力を使っていないか

## 報告の形

- 検出事項（重大度つき）。該当箇所と根拠。**値そのものは書かない**
- 検出 0 件の場合は、**何を検査したか**を列挙する
- 検査できなかった範囲とその理由
- 検査の限界（名称リストの網羅性など）

## してはならないこと

- 自己判断で設定・権限・ルールを変更する
- 検出した秘密情報の値を出力する
- 根拠なく「問題なし」と報告する
- **誤って秘密情報を記録した痕跡を見つけた場合に、自分で履歴を書き換える**
  （STOP して報告する。Public では鍵のローテーションが必要な事故であり、
    履歴の消去だけでは解決しない）

## このスキルが使うツール

読み取りと検査のみ。設定・権限・履歴は変更しない。

**frontmatter に `allowed-tools` は書かない。**
公式仕様では `allowed-tools` は列挙したツールの**使用を許可する**フィールドであり、
制限するものではない（制限は `disallowed-tools`）。
本リポジトリは「共通配布では何も無条件許可しない（`allow` は空）」方針のため、
スキル側から権限を付与しない。
