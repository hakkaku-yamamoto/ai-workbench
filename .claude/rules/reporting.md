# 報告ルール（reporting）

対象：すべてのエージェント・スキル・セッション。
位置づけ：[../../CLAUDE.md](../../CLAUDE.md) の最上位原則 4 の詳細。

---

## 1. 報告の原則

- **実施したことだけを実施したと書く。**
- 未実施・未検証・失敗を省略しない。
- 成果を実際より良く見せない。
- 不確実なことは不確実だと書く。
- 断定は、ツールの出力で裏付けられる内容にのみ使う。

## 2. 事実・推測・実行結果の区別

報告内で以下を明示的に分ける。表現を混ぜない。

| 区分 | 書き方 |
| :- | :- |
| 確認した事実 | 「〜であることを確認した」＋ 根拠（出力、ファイル内容） |
| 実行結果 | 「〜を実行し、〜という結果だった」＋ 実行したコマンド |
| 推測・設計判断 | 「〜と考えられる」「〜を前提とした」＋ 根拠と前提 |
| 未検証・未実施 | 「〜は実施していない」「〜は確認できていない」＋ 理由 |

## 3. 検証結果の書き方

- 実行したコマンドと、その結果を示す。
- テストが失敗したら、失敗したと書き、出力を示す。
- 実行できなかった検証は、**できなかったことと理由**を書く。
- 「実行可能な静的検証のみ実施した」場合は、その範囲を明示する。
- 検証レベル（実行して確認 / 静的に確認 / 未検証）を区別する。

## 4. 完了報告に含める項目

作業完了時は、原則として以下を含める。

1. 事前確認（GATE）の判定結果
2. 対象（リポジトリ、HEAD SHA、ブランチ、環境）
3. 実施した操作の一覧
4. 作成・変更・削除したファイルの一覧と、それぞれの役割
5. 実装した内容
6. 技術的ガードの範囲と**限界**
7. 検証結果（実施した検証と、その結果。未実施も明記）
8. 未解決事項
9. 次に必要な承認
10. 総合判定

## 5. 総合判定

| 判定 | 条件 |
| :- | :- |
| `PASS` | 依頼範囲をすべて完了し、実行可能な検証がすべて成功し、未解決の懸念がない |
| `PASS_WITH_WARNINGS` | 依頼範囲は完了したが、注意事項・未検証項目・設計上の留保・推奨される追加対応がある |
| `BLOCKED` | 事前確認で停止した、途中で STOP 条件に該当した、または依頼範囲を完了できなかった |

### 判定の指針

- 未検証の項目が残っている場合、`PASS` ではなく `PASS_WITH_WARNINGS` とする。
- 「おそらく問題ない」は `PASS` の根拠にならない。
- 一部でも完了できなかった範囲があれば `BLOCKED` を検討する。
- 判定を良く見せるために、未解決事項を省略しない。

## 6. STOP / BLOCKED 時の報告

[agent-conduct.md](agent-conduct.md) の「STOP 時の報告内容」に従う。

加えて、**現在の状態を明示する。**

- 変更されたもの（ファイル、ブランチ、リモート）
- 変更されていないもの
- 元の状態に戻すために必要な操作（必要な場合）

## 7. 報告の形式

- 依頼者が形式を指定した場合は、その形式に従う。
- 単一のコードブロックで提出するよう指定された場合は、**内部に別のコードブロックを作らない。**
  途中で閉じず、最後に 1 回だけ閉じる。
- 秘密情報（鍵、トークン、パスワード、接続文字列）を報告に含めない。値そのものを出力しない。
- 冗長な自己評価・謝罪・反省を書かない。事実と次の行動を書く。
